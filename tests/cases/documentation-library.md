# Two-model library interpretation cases

These are authored expectations for reviewing the [collection program](../../examples/documentation-library/program.md) and [assessment](../../examples/documentation-library/assess.md). They are not observed agent outcomes or executable prose tests. Each case stipulates the stated condition; it does not certify a reference document.

| Supplied condition | Required distinction |
|---|---|
| Both child agreements and collection requirements have supporting evidence of satisfaction | Overall fulfillment can be supported; count two applications of shared definitions, not one shared assessment. |
| Only credit artifacts exist and the index contains only credit | SOFR remains in the required population. An apparently complete one-entry index cannot establish collection fulfillment. |
| SOFR D5 lacks its mandatory locality result; credit D5 has supported interval results | Credit D5 does not replace SOFR D5. Preserve the SOFR content shortfall and its effect on collection fulfillment. |
| The index accurately reports that SOFR is incomplete | Accurate reporting can meet that index obligation while the collection's document-production obligation remains unmet. |
| Both public documents disclose missing institutional facts | Check each public disclosure obligation. Do not add the credit institutional-records mode or infer institutional approval. |
| Child results claim fulfilled but their content has not been examined | Preserve the reported claims and unexamined coverage. The index is not an independent assessment. |
| Artifact content is supported but execution trace is unavailable | Content findings can stand while evidence about permitted execution effects remains unresolved. Do not claim every subject requirement has been checked. |
| A result hash or selection conflicts with the supplied subject | Establish the original subject/agreement or report the conflict. Do not silently assess different bytes or change the selected agreement. |
| A shared definition is listed once in an inventory of definitions | This can correctly inventory source files. It does not count both scoped applications or establish either finding. |
| A summary has all eighteen public D-label applications but omits house and inherited requirements | The selected content-label population is covered, not the complete agreement. Preserve the remaining coverage gap. |
