# Offline controls

The fixtures are authored examples with explicit field and unit bindings. Two supported numerical claims and five deliberately defective bindings cover absent evidence, a conflicting value, swapped methods, wrong units and stale source identity. Their labels were supplied by the author, not produced by a model. They are not a benchmark of executor or evaluator accuracy.

The checker compares the bindings to the retained JSON. It cannot infer a sentence's meaning, discover the correct field for an arbitrary claim, or verify the claimed source unit independently. A numerical match alone does not establish that a sentence is supported. Mutation tests demonstrate detection of changed imported bytes and changed evidence; reproduction controls reject material changes in values, dates, keys and list length.

The separate [model-description cases](cases/model-description.md) and [numerical-evidence cases](cases/numerical-evidence.md) are authored semantic review examples. Their expected interpretations are not executed by the Python tests. They distinguish useful output, missing evidence and contradictions without claiming model accuracy.

[Operating-report cases](cases/operating-reports.md) cover inventory, change, monitoring, remediation, data and calibration reporting. `node scripts/check_monitoring.mjs` checks the synthetic monitoring packet against explicit house thresholds, row identity, coverage and status contradictions. Its mutation controls are not a general contract evaluator; the authored sample report is not parsed or certified by this script.

`node scripts/check_valuation.mjs` checks synthetic price-scale conversions, comparable-subset totals, exact tolerance boundaries, missing/stale/incompatible quotes and offsetting exceptions. It does not reproduce a valuation model or certify source independence.

`node scripts/check_backtesting.mjs` distinguishes observed exceedances from policy treatment of missing/invalid comparisons, preserves separate outcome-series counts and tests timing, identity and coverage controls. Its five-day cases are synthetic; no annual regulatory classification is computed.

`node scripts/check_sofr_change.mjs` applies two authored requirement selections to the unchanged retained SOFR values, with controls for missing support, known violations, equality and incorrect metric binding. It does not run the financial model or evaluate the composed report.

[Report-assessment cases](cases/report-assessment.md) distinguish correct adverse findings, unknown execution effects, binding conflicts, incomplete coverage and an evaluator's own missing result requirements. These are authored expectations awaiting model-backed trials.

`node scripts/check_calibration.mjs` verifies the reproduced table's identity, 22 expected instruments per method, two excluded tenors, rounding precision, missing/duplicate rows and conflicting targets or residuals. Rounded threshold equality remains unresolved where the display cannot establish the exact value. The complete numerical table was generated by the financial model; altered cases and reference report are authored. The script does not evaluate prose or financial soundness.

`node scripts/check_vendor_inventory.mjs` checks a synthetic deployment/register comparison, product/version/configuration/use matching, local observation coverage, signed residual limits and dated-evidence boundaries. It keeps register findings separate from local-check findings, preserves unmatched records and refuses ambiguous population identities. It does not verify vendor material, institutional approvals or prose fulfillment.

`node scripts/check_risk_report.mjs` checks a synthetic daily P&L explanation and alternative stress scenarios. It preserves partial versus complete sums, position and portfolio residuals, interaction differences, assumed hedge effects and known breaches alongside missing evidence. Identity, horizon, basis, units, duplicate observations and exact limits have mutation controls. The script does not validate financial models, causal attribution, hedge feasibility or contract fulfillment.

The risk and outcome checkers also compare selected packet-level bindings against explicitly coded house-policy values. Coherently changing every record to another currency, revision, date or book does not preserve the selected agreement. These are manually supplied bindings for these fixtures, not automatic interpretation of Markdown policy.

`node scripts/check_outcomes.mjs` checks forecast/outcome pairing, maturity, issue/availability times, equal-weight mean absolute error, common-population coverage and undefined relative comparisons at a zero reference error. Missing and late records reverse the apparent winner when populations are aligned. Controls include duplicate identities, invalid dates, incompatible currency, absent outcomes and unmatched records. These are authored statistical arithmetic examples, not a predictive benchmark or measured OpenProse improvement.

The package test copies the selected component files into a fresh directory, checks exact bytes and exports, requires every reusable definition to be selected, and verifies local-reference closure. A missing adopted definition is a negative control. Source integrity remains a separate check because the component package intentionally omits model inputs, provenance records, example programs and test tooling.

`node scripts/check_implementation.mjs` checks the observed Black adapter packets, their receipt/source hashes, selected inputs and units, reference diagnostics, price/parity arithmetic, invalid-input controls and coverage. It preserves known violations alongside missing observations and does not accept a favorable authored producer claim as calculation evidence. Mutation controls cover stale identities, incorrect scope, duplicate/missing cases, changed reference values, warnings, invalid residual flags and failed rejections. Mapping findings are authored source-inspection references; this script does not execute financial code or interpret the report.

`node scripts/check_simulation.mjs` checks selected simulation records against fixed target, stream, input and policy bindings. It verifies moments, standard-error and interval arithmetic, duplicate/grouping relationships, missing observations, conflicting producer claims and exact precision boundaries. Method findings are authored references for the fixed construction; the checker does not infer general sampling independence, verify arbitrary t quantiles, reprice or assess prose.
