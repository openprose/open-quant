# Review a proposed SOFR interpolation change

**For agents.** Execute under the caller's selected OpenProse kernel. The working root is the repository or extracted-package root, two directories above this program.

Adopt [model change](../../contracts/model-change.md) and [sensitivity review](../../contracts/sensitivity-review.md), including their adopted definitions, for one report. Use [the hypothetical change request](inputs/change.md), the retained SOFR [brief](../sofr-curve/inputs/brief.md), [evidence guide](../sofr-curve/inputs/evidence.md), [numerical record](../sofr-curve/inputs/results.json), and the retained base [quotes](../sofr-curve/inputs/quotes.csv) and [fixing](../sofr-curve/inputs/sofr-fixing.json). The [calculation source](../sofr-curve/model/bootstrap.py) may be inspected to identify metric grids and interval definitions; it must not be executed. Sensitivity review is limited to the supplied summary of the specified perturbation, not a reconstructed risk surface. The request defines the hypothetical previous and proposed configurations; the historical brief remains evidence of its own developer's stated choice.

The caller selects `shape` or `shape-and-locality`. In either mode adopt [the shape requirements](house/shape.md). In `shape-and-locality`, also adopt [the locality requirement](house/locality.md). Ask for a missing or unknown mode. All selected requirements apply together; do not weaken one to make the proposed method pass. An unselected house requirement is not an acceptance criterion.

Produce a report under 700 words excluding locators. Identify the mode and exact evidence, compare both methods against the selected numerical criteria, explain the observed tradeoff and relevant limitations, and state whether the proposed B configuration meets those criteria. Discuss the supplied locality evidence in both modes; distinguish reporting it from requiring its limit. Missing required evidence leaves that numerical conclusion unresolved, while any supported breached mandatory criterion prevents an overall positive conclusion. Reporting fulfillment remains a separate finding.

Write only `report.md` and `result.md` to a fresh directory under `results/sofr-change-review/`. The result identifies the program, adopted definitions, selected house files and evidence by hash, checks performed, remaining work and whether the reporting obligation was fulfilled. Return the actual output path.

Use only the selected inputs and definitions; the audience is an operating manager and the required institutional facts are those in the change request. Basic arithmetic is allowed. Preserve sources and earlier outputs. Do not read reference reports or test answers, run models, fetch external sources, change a method, claim approval or execute the hypothetical change. Read boundaries are instructions, not enforced filesystem isolation.
